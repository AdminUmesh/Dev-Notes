### **Immutability of strings**
Strings in C# are immutable, meaning they cannot be changed after creation.

- Any modification creates a new string object
- Original string remains unchanged
- Old object is eligible for garbage collection

```csharp

string s2 = "than the sum of its chars.";

s1 += s2; // creates new string
Console.WriteLine(s1);
```

### **String interpolation**
String interpolation is a feature in C# that allows you to insert variables and expressions directly into a string using $ and {}.

**Syntax**
```csharp
$"Text {variable}"
```

**Example**
```csharp
var jh = (firstName: "Jupiter", lastName: "Hammon", born: 1711, published: 1761);

Console.WriteLine($"{jh.firstName} {jh.lastName} was born in {jh.born}");
Console.WriteLine($"He was published at age {jh.published - jh.born}");
```

### **Using StringBuilder for fast string creation**
StringBuilder is used when you need to perform multiple string modifications efficiently, especially inside loops.

**Why use StringBuilder?**
- Strings are immutable → every change creates a new object
- In loops or heavy operations → this can impact performance
- StringBuilder uses a mutable buffer → avoids creating new objects

**Key Benefits**
- Better performance for repeated string operations
- Can modify characters directly (unlike string)
- Efficient for large or dynamic string building

**Example:** Modify String Without Creating New Object
```csharp
var sb = new StringBuilder("Rat: the ideal pet");
sb[0] = 'C';
Console.WriteLine(sb.ToString());
// Output: Cat: the ideal pet
```

**Example:** Build String in Loop
```csharp
var sb = new StringBuilder();

for (int i = 0; i < 10; i++)
{
    sb.Append(i);
}
Console.WriteLine(sb); // 0123456789
```

# String vs StringBuilder in C#

## String

A **string** in C# is an **immutable** object, which means **its value cannot be changed after it is created**.

Whenever you modify a string, C# creates a **new string object** in memory instead of changing the existing one.

### Example

```csharp
string name = "Umesh";
name += " Singh";
```

Memory:

```
"Umesh"        (Old object)
      ↓
"Umesh Singh"  (New object)
```

Because of this behavior, repeated string concatenation can consume more memory and reduce performance.

---

## StringBuilder

The **StringBuilder** class is used to create **mutable (modifiable)** strings.

Instead of creating a new object every time you modify the text, it updates the existing object, making it much more efficient for frequent string operations.

```csharp
using System.Text;

StringBuilder sb = new StringBuilder();

sb.Append("Umesh");
sb.Append(" Singh");

Console.WriteLine(sb.ToString());
```

Output

```
Umesh Singh
```

---

# String vs StringBuilder

| Feature | String | StringBuilder |
|---------|---------|---------------|
| Object Type | Immutable | Mutable |
| Memory Usage | Creates a new object for every modification | Modifies the same object |
| Performance | Slower for frequent modifications | Faster for frequent modifications |
| Namespace | System | System.Text |
| Thread Safe | Yes (because immutable) | No |
| Best Use | Fixed or rarely changing text | Frequently changing text |

---

# When should you use String?

Use **String** when:

- The value does not change frequently.
- You only perform a few concatenations.
- Readability is more important than performance.

Example:

```csharp
string firstName = "Umesh";
string lastName = "Singh";

string fullName = firstName + " " + lastName;
```

---

# When should you use StringBuilder?

Use **StringBuilder** when:

- Concatenating strings inside loops.
- Building large text or reports.
- Reading file content.
- Generating HTML, XML, or JSON.
- Performing many insert, remove, replace, or append operations.

Example:

```csharp
using System.Text;

StringBuilder sb = new StringBuilder();

for (int i = 1; i <= 1000; i++)
{
    sb.Append(i);
}

Console.WriteLine(sb.ToString());
```

---

# Why are strings immutable in C#?

Strings are immutable to provide:

- Better memory management
- Better security
- Safe sharing of string objects
- Reliable hashing and dictionary lookups

Since strings cannot change, multiple variables can safely reference the same string object.

Example:

```csharp
string s1 = "Hello";
string s2 = "Hello";
```

Memory:

```
      "Hello"
      /     \
    s1       s2
```

If strings were mutable:

```csharp
s1 += " World";
```

Changing `s1` would unexpectedly affect `s2`.

Instead, C# creates a new object:

```
s1 ----> "Hello World"

s2 ----> "Hello"
```

# String Literal

A **string literal** is a fixed string value written directly in the code using double quotes (`"`).

Example:

```csharp
string language = "C#";
string message = "Hello World";
```

Both `"C#"` and `"Hello World"` are string literals.

---

# String Interning (String Literal Pool)

C# stores identical string literals only once in memory. This process is called **string interning**.

Example:

```csharp
string s1 = "Hello";
string s2 = "Hello";
string s3 = "Hello";
```

Memory:

```
        "Hello"
       /   |   \
     s1   s2   s3
```

All three variables reference the same object, reducing memory usage.

---

# Interview Answer

**What is the difference between String and StringBuilder?**

> A **String** is immutable, so every modification creates a new object in memory. It is suitable when the text changes rarely.
>
> A **StringBuilder** is mutable and modifies the same object instead of creating new ones. It provides better performance and lower memory usage when strings are modified frequently, such as inside loops or while generating large text.

---

# Key Points to Remember

- **String** = Immutable
- **StringBuilder** = Mutable
- String concatenation creates a new object.
- StringBuilder modifies the existing object.
- Use **String** for fixed text.
- Use **StringBuilder** for frequently changing text.
- C# does **not** have `StringBuffer`. It only provides `StringBuilder`.
