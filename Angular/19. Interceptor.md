# HTTP Interceptor

An HTTP Interceptor is a mechanism that allows us to check or modify HTTP requests before sending them to the server and handle responses before they reach the application.

## 2. Why do we use it?

An interceptor helps avoid repeating common HTTP logic in every service
or component.

### Common use cases:

-   **Authentication:** Add an access token to outgoing requests.
-   **Logging:** Log request URLs, methods, and response statuses.
-   **Error handling:** Handle common HTTP errors such as `401`, `403`,
    `404`, and `500`.
-   **Loader:** Show a global loading indicator while requests are in
    progress.
-   **Headers:** Add common headers to requests.
-   **Retry and caching:** Apply suitable retry or caching strategies.

## 3. How does it work?

**Request flow:**

1.  A component calls a service.
2.  The service uses Angular `HttpClient`.
3.  The request passes through registered interceptors.
4.  The request reaches the API server.
5.  The response returns through the interceptor chain.
6.  The component receives the response or error.

``` text
Component
   |
   v
Service (HttpClient)
   |
   v
HTTP Interceptor(s)
   |
   v
API Server
   |
   v
HTTP Interceptor(s)
   |
   v
Component receives response
```

`An interceptor can run logic on both the outgoing request and the incoming response.`

## 4. Types of HTTP Interceptors

**Angular supports two approaches:**

  | Type                      | Description                                |
  | ------------------------- | ------------------------------------------ |
  | Functional interceptor    | A function typed as `HttpInterceptorFn`.   |
  | Class-based interceptor   | A class implementing `HttpInterceptor`.    |

Functional interceptors are the recommended approach for new Angular
applications.

## 5. Implement a functional interceptor

### Step 1: Generate an interceptor

``` bash
ng generate interceptor interceptors/logging
```

### Step 2: Write the interceptor

**`logging.interceptor.ts`**

``` typescript
import { HttpInterceptorFn } from '@angular/common/http';

export const loggingInterceptor: HttpInterceptorFn = (req, next) => {
  console.log('API Request:', req.url);

  return next(req);
};
```

**Key parts:**

  | Code                  | Meaning                                                |
  | --------------------- | ------------------------------------------------------ |
  | `HttpInterceptorFn`   | Type for a functional HTTP interceptor.                |
  | `req`                 | The outgoing HTTP request.                             |
  | `next`                | Passes the request to the next handler in the chain.   |
  | `next(req)`           | Continues the request.                                 |

**Important:** If an interceptor does not forward a request using
`next`, the request will not continue to the server.

### Step 3: Register the interceptor

In a standalone Angular application, open `app.config.ts`:

``` typescript
import { ApplicationConfig } from '@angular/core';
import {
  provideHttpClient,
  withInterceptors
} from '@angular/common/http';

import { loggingInterceptor } from './interceptors/logging.interceptor';

export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient(
      withInterceptors([loggingInterceptor])
    )
  ]
};
```

Creating an interceptor is not enough. Register it with
`provideHttpClient()` so Angular can use it.

### Step 4: Make an API call

Example service:

``` typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Injectable({
  providedIn: 'root'
})
export class UserService {
  private http = inject(HttpClient);

  getUsers() {
    return this.http.get(
      'https://jsonplaceholder.typicode.com/users'
    );
  }
}
```

Call the service from a component:

``` typescript
import { Component, inject } from '@angular/core';
import { UserService } from './services/user.service';

@Component({
  selector: 'app-root',
  standalone: true,
  template: `<button (click)="getUsers()">Get Users</button>`
})
export class AppComponent {
  private userService = inject(UserService);

  getUsers() {
    this.userService.getUsers().subscribe({
      next: response => console.log(response),
      error: error => console.error(error)
    });
  }
}
```

When you click **Get Users**, open Chrome DevTools → Console. You should
see the API URL printed by the interceptor.

## 6. Authentication interceptor --- add a token

A common use case is attaching an access token to API requests.

`auth.interceptor.ts`

``` typescript
import { HttpInterceptorFn } from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = 'YOUR_ACCESS_TOKEN'; // Example only

  const modifiedRequest = req.clone({
    setHeaders: {
      Authorization: `Bearer ${token}`
    }
  });

  return next(modifiedRequest);
};
```

Important points:

-   `HttpRequest` objects are immutable.
-   Use `req.clone()` to create a modified copy.
-   `setHeaders` adds or replaces the specified header.
-   In a real application, retrieve the token from an authentication
    service rather than hardcoding it.
-   Only attach credentials to trusted API origins. Do not send tokens
    to arbitrary third-party URLs.

## 7. Error-handling interceptor

Use an interceptor to handle common HTTP errors in one place.

`error.interceptor.ts`

``` typescript
import { HttpInterceptorFn } from '@angular/common/http';
import { catchError, throwError } from 'rxjs';

export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  return next(req).pipe(
    catchError(error => {
      if (error.status === 401) {
        console.log('Unauthorized');
      } else if (error.status === 403) {
        console.log('Forbidden');
      } else if (error.status === 404) {
        console.log('API not found');
      } else if (error.status === 500) {
        console.log('Internal server error');
      }

      // Forward the error so the calling service/component can handle it too.
      return throwError(() => error);
    })
  );
};
```

`catchError()` handles an error in the observable stream. `throwError()`
re-emits it so the caller can also respond to the failure.

## 8. Loader interceptor

An interceptor can show a global loader while an HTTP request is active.

`loader.interceptor.ts`

``` typescript
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { finalize } from 'rxjs';
import { LoaderService } from '../services/loader.service';

export const loaderInterceptor: HttpInterceptorFn = (req, next) => {
  const loader = inject(LoaderService);

  loader.show();

  return next(req).pipe(
    finalize(() => {
      loader.hide();
    })
  );
};
```

`finalize()` runs when the observable completes, errors, or is
unsubscribed. This makes it useful for cleanup such as hiding a loader.

**Important:** If multiple requests can run at the same time, use a
request counter in `LoaderService`. A simple boolean can hide the loader
too early when one request finishes while another is still running.

## 9. Register multiple interceptors

Register multiple interceptors in `app.config.ts`:

``` typescript
provideHttpClient(
  withInterceptors([
    loggingInterceptor,
    authInterceptor,
    errorInterceptor,
    loaderInterceptor
  ])
)
```

The order matters:

-   Outgoing requests pass through interceptors in the listed order.
-   Incoming responses pass back through the chain in reverse order.

## 10. Important terms

| Term | Purpose |
|---|---|
| `HttpInterceptorFn` | Defines a functional interceptor. |
| `req` | Represents the outgoing HTTP request. |
| `next` | Continues the interceptor chain. |
| `next(req)` | Forwards the request. |
| `req.clone()` | Creates a modified copy of an immutable request. |
| `setHeaders` | Adds or replaces request headers. |
| `withInterceptors()` | Registers functional interceptors. |
| `provideHttpClient()` | Configures Angular's `HttpClient`. |
| `catchError()` | Handles errors in an observable stream. |
| `finalize()` | Runs cleanup when the observable terminates or is unsubscribed. |


## 11. Quick revision

**Q: What is an HTTP Interceptor?**\
An Angular mechanism that intercepts HTTP requests and responses to
apply common logic centrally.

**Q: Why do we use HTTP Interceptors?**\
To avoid repeating logic such as adding tokens, logging, error handling,
and loader management in every API call.

**Q: What is the difference between functional and class-based
interceptors?**\
A functional interceptor is a function typed as `HttpInterceptorFn`; a
class-based interceptor is a class implementing `HttpInterceptor`.

**Q: Why do we use `req.clone()`?**\
HTTP requests are immutable, so cloning creates a modified request.

**Q: What does `next(req)` do?**\
It forwards the request to the next interceptor or the HTTP backend.

**Q: Why use `finalize()` for a loader?**\
It runs on completion, error, or unsubscription, allowing the loader to
be hidden in every termination case.

**Q: Where do we register functional interceptors?**\
Inside `provideHttpClient(withInterceptors([...]))`, commonly in
`app.config.ts`.
