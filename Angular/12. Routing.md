# Routing
Angular show different components based on the URL — without reloading the page. `When the user visits a specific URL, show a specific component on the screen.`

---

## Step 1. Define Routes

In `app.routes.ts`:

```ts
import { Routes } from '@angular/router';
import { HomeComponent } from './home/home.component';
import { AboutComponent } from './about/about.component';

export const appRoutes: Routes = [
  {path: '', redirectTo: 'home', pathMatch: 'full'}
  {path: '', redirectTo: 'home', pathMatch: 'prefix'}
  { path: '', component: HomeComponent },
  { path: 'home', loadComponent: () => import('./about/about.component').then(m => m.AboutComponent) },
  { path: 'admin', loadChildren: () => import('./admin/admin.routes').then(m => m.ADMIN_ROUTES)},
  {
  path: 'admin',
  component: AdminComponent,
  children: [
    { path: 'dashboard', component: DashboardComponent },
    { path: 'users', component: UsersComponent },
    { path: 'settings', component: SettingsComponent }
  ]
  },
  { path: '**', redirectTo: '' }
];
```

### compocomponent: 
Direct component loading

**What happens?**
1. Angular imports HomeComponent directly.
2. The component is included in the application's eagerly loaded code.
3. When the user visits /home, Angular displays it.

**Think of it this way:** The component is already part of the loaded application code. Angular just needs to display it.

`Use this when eager loading is suitable, for example for small components or routes you want available immediately.`

### loadComponent 
Lazy-load one component

**What happens?**
1. Angular doesn't statically import HomeComponent through the routing file.
2. When the user navigates to /home, Angular loads the component dynamically.
3. The component can be placed in a separate JavaScript bundle.
4. Angular displays the component.

**Think of it this way:** Don't load this page's code until the user needs it.

`Use this when you have an individual page that you want to lazy-load.`

### loadChildren 
Lazy-load a group of routes

**Imagine your application has an Admin section:**
- /admin/dashboard
- /admin/users
- /admin/settings

Instead of defining all these routes in your main routing file, you can create a separate route configuration.

**admin/admin.routes.ts**

```ts
import { Routes } from '@angular/router';

export const ADMIN_ROUTES: Routes = [
  {
    path: 'dashboard',
    loadComponent: () =>
      import('./dashboard/dashboard.component')
        .then(m => m.DashboardComponent)
  },
  {
    path: 'users',
    loadComponent: () =>
      import('./users/users.component')
        .then(m => m.UsersComponent)
  },
  {
    path: 'settings',
    loadComponent: () =>
      import('./settings/settings.component')
        .then(m => m.SettingsComponent)
  }
];
```

**Main routing file:**

```ts
export const routes: Routes = [
  {
    path: 'admin',
    loadChildren: () =>
      import('./admin/admin.routes')
        .then(m => m.ADMIN_ROUTES)
  }
];
```

`Now Angular loads the Admin route configuration when the user visits an Admin URL.`

**For example:**
- /admin/dashboard
- /admin/users
- /admin/settings

**Important:** loadChildren can load a child route configuration or an NgModule. Modern standalone Angular applications commonly use route configuration files.

**Other KeyWord**

**redirectTo –** Redirects the user to another route. Example: / → /home.

**pathMatch: 'full' –** Matches only when the complete remaining URL path matches. Example: / → /home, but not /home/101.

**pathMatch: 'prefix' –** Matches when the route path matches the beginning of the URL. Example: /employee matches /employee/101.

**(Wildcard) –** Handles URLs that don't match any defined route (typically redirects to a 404 page). Example: /abc → /not-found.

### children 
Nested Routing (Child Routing)

**1. How it work**
```ts
// Configure in Route
{
  path: 'admin',
  component: AdminComponent,
  children: [
    { path: 'dashboard', component: DashboardComponent },
    { path: 'users', component: UsersComponent },
    { path: 'settings', component: SettingsComponent }
  ]
}
```

**Important:** The child components will render only inside the AdminComponent's <router-outlet>.

**2. Admin component HTML**
```html
<h1>Admin Panel</h1>

<nav>
  <a routerLink="dashboard">Dashboard</a>
  <a routerLink="users">Users</a>
  <a routerLink="settings">Settings</a>
</nav>

<router-outlet></router-outlet>
```
**Note:** `It will work when you call admin, admin/users, admin/settings etc`

### Step 2: Provide Routes in `main.ts`

```ts
import { provideRouter } from '@angular/router';
import { appRoutes } from './app/app.routes';

bootstrapApplication(AppComponent, {
  providers: [provideRouter(appRoutes)]
});
```

---

### Step 3: Add `<router-outlet>` in `app.component.html`

```html
<h1>My Angular App</h1>
<nav>
  <a routerLink="/">Home</a> |
  <a routerLink="/about">About</a>
</nav>

<router-outlet></router-outlet>
```

# Eager Loading vs Lazy Loading
## Eager Loading vs Lazy Loading in Angular

| Eager Loading | Lazy Loading |
|---|---|
| Loads components upfront. | Loads components when required. |
| Increases initial loading cost for large applications. | Reduces initial loading cost. |
| Uses `component`. | Uses `loadComponent` or `loadChildren`. |
| Suitable for small components/features. | Suitable for large features/modules. |

## Eager Loading Example
```ts 
{
  path: 'about',
  component: AboutComponent
}
```

## Lazy Loading Example

### Using loadComponent:
``` ts
{
  path: 'about',
  loadComponent: () =>
    import('./about/about.component')
      .then(m => m.AboutComponent)
}
```

### Using loadChildren:
```ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes')
      .then(m => m.ADMIN_ROUTES)
}
```
