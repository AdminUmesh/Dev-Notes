# Application Programming Interface (API)

## What is an API?

An **API (Application Programming Interface)** is a set of rules that allows two software applications to communicate with each other.

### Easy Example

Think of an API as a **waiter** in a restaurant.

* **Client** → You
* **API** → Waiter
* **Server** → Kitchen

Flow:

```text
Client → API → Server
Client ← API ← Server
```

**Real Example**

A weather app sends a request to a weather server through an API. The server processes the request and sends back weather information.

---

# Types of APIs

## 1. REST API ⭐ (Most Common)

* Uses HTTP methods (GET, POST, PUT, PATCH, DELETE)
* Simple and fast
* Mostly returns **JSON**
* Most commonly used in web applications

---

## 2. SOAP API

* Uses XML
* More secure and strict
* Mainly used in banking and enterprise applications

---

## 3. WebSocket API

* Supports real-time communication
* Two-way communication between client and server

**Examples**

* Chat applications
* Live cricket scores
* Stock market updates

---

## 4. OpenAPI (Swagger)

* Used to document APIs
* Helps test APIs
* Can automatically generate API documentation

---

# HTTP Methods

| Method  | Purpose                       |
| ------- | ----------------------------- |
| GET     | Retrieve data                 |
| POST    | Create new data               |
| PUT     | Update the entire resource    |
| PATCH   | Update only specific fields   |
| DELETE  | Delete data                   |
| HEAD    | Get only response headers     |
| OPTIONS | Check allowed HTTP methods    |
| TRACE   | Debug request by returning it |

---

# Common HTTP Methods

## GET

**Purpose:** Retrieve data

* Does **not** change data
* Safe to use

**Example**

```http
GET /users
GET /users/1
```

---

## POST

**Purpose:** Create new data

* Sends data in the request body
* Changes server data

**Example**

```http
POST /users
```

---

## PUT

**Purpose:** Update the **entire** resource

**Example**

```http
PUT /users/1
```

---

## PATCH

**Purpose:** Update **only required fields**

**Example**

```http
PATCH /users/1
```

Example:

* Update Name
* Update Email
* Update Phone Number

---

## DELETE

**Purpose:** Delete a resource

**Example**

```http
DELETE /users/1
```

---

# GET vs POST

| Feature             | GET           | POST             |
| ------------------- | ------------- | ---------------- |
| Purpose             | Retrieve data | Create/Send data |
| Data Location       | URL           | Request Body     |
| Changes Server Data | ❌ No          | ✅ Yes            |
| Cached              | ✅ Yes         | ❌ Usually No     |
| Security            | Less Secure   | More Secure      |

### Example

**GET**

```http
GET /users/5
```

**POST**

```http
POST /users

{
    "name": "Umesh",
    "age": 25
}
```

---

# Can POST be used to fetch data?

**Yes.**

Although GET is the standard method for retrieving data, POST can also be used.

### When?

### 1. Complex Queries

When request data is too large for a URL.

Example:

* Advanced search
* Multiple filters

---

### 2. Sensitive Data

When you don't want request data to appear in the URL.

Examples:

* Login
* Confidential search filters

---

# Can GET be used to insert data?

**Technically, Yes.**

**Recommended? → No ❌**

### Why?

### 1. GET is meant only for retrieving data.

---

### 2. Data appears in the URL.

Example:

```http
GET /createUser?name=Umesh&password=123
```

This information can be visible in:

* Browser history
* Server logs
* Shared URLs

---

### 3. GET requests can be cached.

This may accidentally create duplicate records.

### Difference between PUT and PATCH?

**PUT**

* Updates the complete resource.

**PATCH**

* Updates only selected fields.

---

### Can POST be used to retrieve data?

**Yes.**

Used when:

* Request data is large
* Data is sensitive

---

### Can GET be used to insert data?

Technically **Yes**, but it should **not** be used because:

* It breaks REST principles.
* Data appears in the URL.
* GET requests are cached.
* It may create duplicate records.

# Easy Trick to Remember

* **GET** → Get data
* **POST** → Post/Create data
* **PUT** → Put everything (Full Update)
* **PATCH** → Patch only damaged parts (Partial Update)
* **DELETE** → Delete data
